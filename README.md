# Домовед

Сервис для жителей многоквартирных домов и управляющих компаний внутри MAX. Житель сообщает о проблеме, общается с УК и соседями, получает объявления своего дома. Сотрудник УК обрабатывает обращения в веб-кабинете.

Проект команды **«Облачный Код»** для хакатона MAX по направлению «Умный город».

## Демонстрация

| Интерфейс | Адрес |
| --- | --- |
| Бот и вход в мини-приложение | [Домовед в MAX](https://max.ru/t282_hakaton_max_bot) |
| Веб-кабинет УК | [201.34.159.33/staff/](https://201.34.159.33/staff/) |
| Документация API | [Swagger](https://201.34.159.33/api/docs) |
| Базовый адрес API | `https://201.34.159.33/api/v1` |

В демонстрационном каталоге — УК «Домовед» и пять домов в Казани на улице Солнечной. Вход жителя выполняется через MAX, вход сотрудника — по логину и паролю. В тестовом режиме привязка квартиры принимается автоматически; ручное рассмотрение заявок также поддерживается.

## Возможности

| Для жителя | Для управляющей компании |
| --- | --- |
| Регистрация и несколько квартир в одном аккаунте | Рассмотрение заявок на привязку квартир |
| Обращение с местом на плане дома и фотографиями | Создание обращения от имени жителя, фильтры и смена статусов |
| История обращения и чат с УК | Переписка с автором, изменение приоритета, отклонение с причиной |
| План подъездов, этажей и квартир, сообщения соседям | Работа с обращениями назначенных домов |
| Уведомления в приложении и через бота | Центр уведомлений о новых событиях |
| Камеры: снимки и эфир для поддерживаемых источников | Рассмотрение заявок на общедоступные камеры |
| Начисления ЖКХ и передача показаний | Объявления, рассылки и запланированные работы |
| Приглашение соседей по ссылке или QR-коду, листовка для подъезда | Подключение домовых чатов MAX и закреплённого меню бота |

Мини-приложение поддерживает светлую и тёмную темы, обучение при первом входе и переходы в нужный дом из чата или приглашения.

### Для жителя

- **Квартиры и план дома.** В одном аккаунте можно привязать несколько квартир и переключаться между ними. На плане доступны подъезды, этажи, квартиры и общие зоны. В чужой квартире доступна связь с соседями, сообщение о квартирной проблеме создаётся только для своей квартиры.
- **Обращения.** Место выбирается на плане, к описанию прикладываются фотографии. В списке есть поиск и фильтры по статусам, в карточке — история изменений и переписка с УК. Черновик можно отложить в пределах текущего сеанса.
- **Переписка.** Жители общаются между квартирами и обсуждают своё обращение с сотрудником УК. В чатах поддерживаются текст и фотографии, вложения открываются крупным планом.
- **Камеры.** Можно добавить свою камеру по ссылке, указать место установки и выбрать личный или общедоступный режим. Приложение определяет тип подключения и показывает результат проверки. Общедоступная камера становится видна соседям после одобрения УК; личная остаётся доступна владельцу.
- **ЖКХ.** В разделе отображаются лицевой счёт, период, начисления и сумма квитанции. Показания счётчиков передаются одной формой. Экран оплаты демонстрационный, без списания денег.
- **Работы и состояние дома.** Главная показывает предстоящие и текущие работы с местом, сроками и описанием. Раздел «Здоровье дома» отображает показатель по обращениям и его историю за 7, 14 или 30 дней.
- **Уведомления и контакты.** Из центра уведомлений можно открыть обращение, переписку или другое связанное событие и отметить уведомление прочитанным. Контакты УК доступны отдельным разделом; в настройках выбираются тема и категории личных уведомлений.

### Для управляющей компании

- **Обработка обращений.** Сотрудник видит обращения назначенных домов, ищет их по номеру или тексту, фильтрует по дому, статусу и приоритету. В карточке доступны фотографии, история, чат с автором, смена статуса и приоритета. Отклонение сопровождается причиной.
- **Ручной приём.** Обращение можно создать от имени жителя в кабинете УК: выбрать заявителя из списка или указать его данные вручную, заполнить место и описание проблемы.
- **Регистрация жителей.** Заявки на привязку квартиры можно принять или отклонить. Удаление принятой заявки снимает только соответствующую привязку, сохраняя остальные квартиры и аккаунт жителя.
- **Объявления и работы.** Рассылка сохраняется как черновик с выбором темы, домов, получателей и каналов доставки. Предпросмотр показывает текст и аудиторию, история — результат отправки. Для запланированных работ задаются место и сроки, включая неизвестный срок окончания; начавшуюся работу можно завершить вручную.
- **Адресные сообщения.** Рассылку можно отправить жителям выбранных домов или отдельным людям. Поиск получателей работает по имени, MAX ID, адресу и квартире. Личные сообщения доступны жителям, уже взаимодействовавшим с ботом.
- **Камеры, контакты и события.** Сотрудник рассматривает заявки на общедоступные камеры и указывает причину отклонения. Контакты УК редактируются для одного или нескольких домов. Новые события собраны в центре уведомлений со ссылками на соответствующие разделы.

### Приглашения и домовые чаты

Для каждого дома доступна постоянная ссылка-приглашение, QR-код и листовка A4 с Жориком, адресом и кодом для входа. Житель может скопировать ссылку или скачать листовку в разделе «Ещё → Пригласить соседей».

Кабинет УК связывает дом с группой MAX через одноразовую команду подключения. Бот закрепляет приветственное сообщение с кнопками мини-приложения. У каждой кнопки сохраняются нужный дом и раздел: обращение из чата одного дома не открывается в другом доме пользователя. При отсутствии привязки приложение предлагает регистрацию по адресу из ссылки.

## Первый вход

1. **Открытие.** Житель запускает мини-приложение из бота MAX, нажимает кнопку в домовом чате или сканирует QR-код приглашения. Профиль создаётся по данным MAX, отдельный пароль для жителя не нужен.
2. **Привязка квартиры.** Если подходящей квартиры ещё нет, открывается регистрация: ФИО, управляющая компания, дом и квартира. Имя можно исправить. При переходе по ссылке конкретного дома УК и адрес уже подставлены.
3. **Подтверждение.** В тестовом режиме заявка принимается автоматически. При ручном рассмотрении житель видит ожидание решения УК; доступ к данным дома появляется после одобрения.
4. **Переход в приложение.** Обычный вход и приглашение по QR-коду дома ведут на главную. После регистрации через кнопку домового чата открывается исходный раздел: создание обращения, обращения дома или контакты УК. Создание обращения начинается с выбора места проблемы.
5. **Обучение.** При первой регистрации через обычный вход или приглашение дома показывается знакомство с приложением. Кнопки домового чата откладывают обучение, чтобы сразу открыть выбранное действие. Пройденное или пропущенное обучение не запускается автоматически повторно; повтор доступен в «Ещё».

Если квартира уже привязана, повторная регистрация не требуется. При переходе в другой, ещё не привязанный дом приложение показывает его адрес и предлагает добавить квартиру. Сама ссылка или QR-код не предоставляют доступ к чужим данным.

## Как проходит обращение

1. Житель открывает мини-приложение из MAX, домового чата или по QR-коду. Если квартира ещё не привязана, проходит регистрацию. Ссылка дома подставляет УК и адрес.
2. Выбирает место проблемы: двор, подъезд или свою квартиру. Добавляет описание и до 10 фотографий.
3. Обращение появляется у сотрудника УК. Сотрудник уточняет детали в чате и меняет статус.
4. Житель видит историю и уведомления, открывает обращение и отвечает в том же чате.

Статусы: **Новое → Принято → Назначен исполнитель → В работе → Решено**. Статус «Назначен исполнитель» фиксирует этап обработки; отдельного справочника исполнителей пока нет.

Дворовые обращения видны жильцам дома, подъездные — жильцам соответствующего подъезда, квартирные — только автору. Сотруднику доступны обращения назначенных ему домов. Удаление привязки одной квартиры сохраняет аккаунт, другие квартиры и обращения.

### Помощь Алисы

В боте модель Yandex Cloud предлагает заголовок, подкатегорию, приоритет и место проблемы. Перед отправкой житель может изменить результат. В мини-приложении Алиса определяет только приоритет, сохраняя заполненные поля. При недоступности модели обращение сохраняется со средним приоритетом; текст и фотографии не теряются.

### Домовые чаты и уведомления

В подключённом чате бот размещает закреплённое приветствие с кнопками «Сообщить о проблеме», «Обращения дома» и «Контакты УК». В общую группу поступают объявления УК. Статусы обращений и личная переписка в домовой чат не публикуются.

Личные уведомления учитывают настройки жителя, прочтение и присутствие в соответствующей переписке. В мини-приложении и кабинете УК есть отдельные центры уведомлений. Рассылки поддерживают домовые чаты и личные сообщения жителям, взаимодействовавшим с ботом.

## Архитектура

- **Мини-приложение:** Next.js, React, TypeScript, CSS Modules.
- **API:** FastAPI, SQLAlchemy, PostgreSQL, миграции Alembic.
- **Бот MAX:** Python, получение событий через polling.
- **Камеры:** отдельный camera-worker для подключения к внешним источникам.
- **Развёртывание:** Docker Compose и Nginx.

Бот и API используют общие модели и одну базу PostgreSQL. Связь жителя с квартирой хранится отдельно: у одного человека может быть несколько квартир, у одной квартиры — несколько жильцов. Фотографии находятся в общем файловом хранилище, доступ к ним проверяет API.

## Запуск

Для локального запуска используются Docker Desktop с Linux-контейнерами и Docker Compose v2. Команды выполняются из корня репозитория в PowerShell.

```powershell
Copy-Item .env.docker.example .env.docker
```

В `.env.docker` задаются `POSTGRES_PASSWORD` и `LOCAL_SESSION_SECRET`. Для подключения бота и Алисы используются `BOT_TOKEN`, `YANDEX_API_KEY` и `YANDEX_FOLDER_ID`. Файлы с рабочими секретами исключены из Git.

```powershell
docker compose --env-file .env.docker -f compose.yaml -f compose.local.yaml up -d --build
```

Compose запускает PostgreSQL, применяет миграции, создаёт локального тестового жителя с квартирой и поднимает API и мини-приложение.

| Адрес | Сервис |
| --- | --- |
| `http://localhost:3000` | Мини-приложение с локальным входом |
| `http://localhost:8000/staff/` | Кабинет УК |
| `http://localhost:8000/api/docs` | Swagger |
| `http://localhost:8000/health/ready` | Состояние API и БД |

Запуск с ботом:

```powershell
docker compose --env-file .env.docker -f compose.yaml -f compose.local.yaml --profile bot up -d --build
```

Один токен MAX обслуживает один экземпляр polling-бота. Локальный запуск бота с токеном работающего серверного экземпляра создаёт конфликт получения событий.

### Сотрудник УК

Аккаунт сотрудника создаётся отдельно от аккаунта жителя. Команда `list` выводит каталог домов, `create` создаёт сотрудника с доступом к выбранным ID домов:

```powershell
docker compose --env-file .env.docker -f compose.yaml -f compose.local.yaml exec api python -m scripts.manage_staff list
docker compose --env-file .env.docker -f compose.yaml -f compose.local.yaml exec api python -m scripts.manage_staff create manager --name "Сотрудник УК" --house 1 --house 2
```

Пароль вводится в терминале, минимум 12 символов. Команда `assign` заменяет весь список доступных сотруднику домов.

## API и тесты

Текущий контракт приложения: [OpenAPI YAML](backend/openapi.yaml) и [JSON](backend/openapi.json). Снимок публичного контракта находится в [backend/evaluation/](backend/evaluation/).

[DATA-API.yaml](backend/DATA-API.yaml) описывает 26 проверок API: методы, параметры, роли, коды ответа и схемы данных. Формат конфигурации — [DATA-API.schema.json](backend/DATA-API.schema.json). [test-data.json](backend/test-data.json) содержит данные изолированной тестовой базы, [test-accounts.example.json](backend/test-accounts.example.json) — структуру тестовых ролей.

Авторизация жителя использует подписанные данные MAX. Кабинет УК работает через cookie-сессию и CSRF; для API-клиентов сотрудника также доступен Bearer-токен.

Проверки мини-приложения из `mini-app/`:

```powershell
npm ci
npm run lint
npm run typecheck
npm test
npm run build
```

Проверки backend из `backend/` с установленными зависимостями `requirements-dev.txt`:

```powershell
python -m ruff check .
python -m pytest -q
python -m pip check
```

Тесты PostgreSQL используют отдельную БД из `TEST_POSTGRES_URL`; без этой переменной они пропускаются. Остальные тесты выполняются на временной базе.

## Ограничения демонстрационной версии

- Оплата ЖКХ демонстрационная: выбор СБП или карты не приводит к списанию. PDF-квитанции не подключены, показания не пересчитывают уже выставленную квитанцию.
- Регистрация использует каталог УК, домов и квартир. Подтверждение права проживания внешними сервисами не реализовано. Автоматическое принятие заявок включается тестовым режимом.
- Реальные камеры зависят от доступности источника; эфир без звука поддерживается для совместимых подключений. Демонстрационные камеры используют подготовленные изображения.
- «Здоровье дома» рассчитывается по обращениям, а не по инженерным датчикам.
- Уведомления в MAX доставляются работающим ботом. Браузерные push-уведомления не реализованы.
