# Домовед API

Backend на FastAPI и SQLAlchemy с PostgreSQL. API и бот используют общие модели из `app/database/`; схема базы обновляется через Alembic. Кабинет УК расположен в `smart_city_api/staff_web/` и доступен по `/staff/`.

Запуск проекта в Docker описан в [DOCKER.md](../DOCKER.md).

## Запуск без Docker

Требуются Python 3.14 и PostgreSQL 17. Создайте базу и пользователя, скопируйте [.env.example](.env.example) в `.env` и заполните настройки. Если `.env` уже существует, используйте его.

Из каталога `backend` в PowerShell:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
$env:PYTHONPATH = ".."
.\.venv\Scripts\python.exe -m alembic upgrade head
.\.venv\Scripts\python.exe -m uvicorn smart_city_api.main:app --host 127.0.0.1 --port 8000 --loop smart_city_api.runtime:loop_factory
```

На Linux используйте `.venv/bin/python` и `export PYTHONPATH=..`. Документация API доступна по `/docs`, актуальный контракт — по `/openapi.json`. Проверка подключения к базе: `/health/ready`.

## Настройки

| Переменная | Назначение |
| --- | --- |
| `DATABASE_URL` | Подключение к PostgreSQL с драйвером `postgresql+psycopg`; специальные символы пароля кодируются в URL |
| `BOT_TOKEN` | Токен MAX, общий для API и бота |
| `CORS_ORIGINS` | JSON-массив разрешённых адресов мини-приложения |
| `SESSION_COOKIE_SECURE` | `false` для локального HTTP, `true` для HTTPS |
| `LOCAL_LOGIN_ENABLED` | Локальный вход для разработки |
| `LOCAL_SESSION_SECRET` | Секрет локальной сессии |
| `ONBOARDING_TEST_MODE` | Демонстрационная УК, пять домов и автоматическое принятие заявок; в корневом Compose включён по умолчанию |
| `SAMPLE_DATA_ENABLED` | Дополнительные тестовые квартиры, обращения и начисления |
| `MEDIA_ROOT` | Каталог фотографий, общий с ботом |
| `MAX_AUTH_AGE_SECONDS` | Допустимый возраст параметров входа MAX; по умолчанию 3600 секунд |
| `STAFF_SESSION_HOURS` | Срок сессии сотрудника; по умолчанию 8 часов |

Для локального входа включите `LOCAL_LOGIN_ENABLED`, задайте `LOCAL_SESSION_SECRET` и выполните `python -m scripts.seed_local` в подготовленном окружении. Команда создаёт тестового жителя с квартирой. На публичном сервере локальный вход выключен.

## Авторизация и регистрация

`POST /api/v1/auth/max` проверяет подписанные параметры MAX, создаёт пользователя при первом входе и выдаёт HttpOnly-cookie на один час. Также поддерживается `Authorization: Bearer <initData>`. Без авторизации защищённые маршруты возвращают 401.

`GET /api/v1/registration` возвращает состояние регистрации и каталог УК. `POST` принимает ФИО, УК, дом и номер квартиры. При `ONBOARDING_TEST_MODE=true` заявка принимается автоматически; иначе её рассматривает сотрудник. Пользователь может добавить несколько квартир, а одну квартиру могут привязать несколько жильцов.

Доступ к данным определяется привязками квартир. Обращения в квартире доступны её жильцам и автору при наличии доступа к дому; обращения в общих зонах — жильцам дома. Доступ к фотографиям проверяется отдельно. Запросы на запись с cookie-сессией проверяют Origin.

## Основные маршруты

Пути в таблице указаны относительно `/api/v1`.

| Путь | Назначение |
| --- | --- |
| `/me` | Профиль, квартиры и дома пользователя |
| `/houses/{id}/apartments` | Структура квартир по подъездам и этажам |
| `/houses/{id}/issues` | Список и создание обращений |
| `/houses/{id}/issues/with-photos` | Создание обращения с фотографиями |
| `/issues/{id}` | Карточка и история обращения |
| `/issues/{id}/photos/{photo_id}` | Фотография обращения |
| `/apartments/{id}/messages` | Чтение и отправка сообщений |
| `/apartments/{id}/utilities` | Лицевой счёт, квитанция и приборы |
| `/meters/{id}/readings` | Передача показаний |
| `/houses/{id}/cameras`, `/cameras/{id}/preview` | Камеры и доступные кадры |
| `/houses/{id}/works`, `/houses/{id}/contacts` | Работы по дому и контакты УК |
| `/staff` | API кабинета сотрудника |

Списки квартир, обращений и сообщений используют cursor-пагинацию. При создании обращений и сообщений передаётся UUID `request_id`: повтор с тем же содержимым возвращает существующую запись, с другим — ошибку 409.

## Кабинет УК

Сотрудник входит по логину и паролю и работает только с назначенными домами: рассматривает обращения и заявки на квартиры, меняет статусы, отправляет сообщения и редактирует контакты. Отклонение обращения требует причины: обращение скрывается из списков, бот отправляет автору уведомление. В принятых заявках доступно удаление аккаунта вместе с его обращениями и привязками; общие данные дома и аккаунты других жильцов сохраняются. Удаление недоступно, если у пользователя есть данные в домах другой УК.

В контактах отображаются назначенные сотруднику дома зарегистрированных УК. Тестовые дома получают демонстрационные номера, которые можно заменить в редакторе. Уведомления жителям доставляет бот.

Создание сотрудника из каталога `backend`:

```powershell
python -m scripts.manage_staff list
python -m scripts.manage_staff create manager --name "Сотрудник УК" --house 1 --house 2
```

Команда запросит пароль в терминале. Укажите ID существующих домов. Для изменения назначений используется `assign`; он заменяет список домов целиком.

## Проверки

```powershell
python -m ruff check .
python -m pytest -q
python -m pip check
```

Для тестов PostgreSQL задайте `TEST_POSTGRES_URL` отдельной тестовой базы. Без этой переменной соответствующие тесты пропускаются. После изменения моделей примените `python -m alembic upgrade head`.

Платёжный провайдер и видеотрансляции не подключены. Передача показаний не пересчитывает выставленную квитанцию.
