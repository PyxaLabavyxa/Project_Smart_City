# Регистрация жителей

Первый вход в MAX-бот или мини-приложение создаёт только профиль. ФИО из базы (для нового профиля — имя из подписанных данных MAX) можно исправить. Далее житель выбирает УК, дом и номер квартиры. Одинаковые ФИО не используются как подтверждение личности: оба канала связываются по MAX ID.

`GET /api/v1/registration` возвращает имя, состояние и каталог УК. `POST /api/v1/registration` создаёт заявку. Наличие назначенной квартиры означает завершённую регистрацию; уже привязанные квартиры сохраняются. Случайные квартиры больше не назначаются при входе, даже с прежним `SAMPLE_DATA_ENABLED=true`.

`ONBOARDING_TEST_MODE=true` должен быть одинаковым у API и бота. В Compose он включён по умолчанию для этой демонстрации. API/бот при запуске создают одну УК «ДомПульс» и пять домов в г. Казани на ул. Солнечной, 1–5 (9, 7, 5, 12 и 10 этажей), квартиры и по два явно отмеченных тестовых обращения на дом. Заполнение повторяемое, существующие данные жителей не удаляются. Автопринятие и привязка квартиры выполняются в одной транзакции. Пользовательская блокировка не позволяет двум каналам создать две заявки одновременно в PostgreSQL.

Перед запуском обновления примените миграции `python -m alembic upgrade head` из backend. Для доступа существующего сотрудника УК к новым пяти домам выполните из backend:

```sh
python -m scripts.seed_registration --staff-login <логин-сотрудника>
```

Команда добавляет пять домов к текущим назначениям сотрудника, сохраняя старые. Не создаёт учётных записей и паролей. В Docker: `docker compose --env-file .env.docker run --rm api python -m scripts.seed_registration --staff-login <логин-сотрудника>`.

Слева в кабинете УК доступна вкладка «Заявки»: ФИО, адрес/квартира, источник, дата и статус. Автопринятые заявки показаны с отметкой; повторное решение для них недоступно. Кнопки «Принять» и «Отклонить» работают только для ожидающих заявок. Сервер проверяет назначенные сотруднику дома и CSRF. При отключённом тестовом режиме заявки ожидают ручного решения; отклонённую заявку можно подать заново. Каталог тестовых домов не удаляется при отключении режима.

Проверка: войти новым пользователем напрямую в мини-приложение, исправить ФИО, выбрать дом и квартиру, отправить; открыть бот — он показывает меню без повторной анкеты. Повторить в обратном порядке. Уже открытое мини-приложение проверяет завершение каждые 10 секунд и при возвращении фокуса. Старое сообщение бота при нажатии тоже проверяет базу. Для проверки с существующим пользователем не удаляйте его квартиры: используйте новый MAX-профиль или отдельную тестовую базу.

Старые скрипты заполнения демонстрационных платёжных данных остаются явными административными инструментами, но не вызываются из регистрации. В тестовом режиме каталог домов также получает демонстрационные камеры, счета, квитанции и счётчики из прежнего набора примеров. Заполнение не назначает квартиры, не создаёт дополнительные обращения и не перезаписывает существующие счета, показания или камеры. Для реального режима это заполнение отключено вместе с `ONBOARDING_TEST_MODE`.

В окне «Мои квартиры» мини-приложения можно добавить ещё одну квартиру: запрос использует `additional: true`. Одна квартира доступна нескольким членам семьи; повторная заявка на уже привязанную тому же человеку квартиру не создаёт дубликат. Для дополнительной квартиры результат определяется полем `application_status`, поскольку `complete` уже истинно. Первичная регистрация сохраняет идемпотентность между ботом и мини-приложением.

Бот обновляет сообщение регистрации до «Добро пожаловать», а главное меню отправляет следующим сообщением. Если редактирование недоступно, приветствие отправляется отдельно. После появления квартиры мини-приложение автоматически предлагает обучение один раз на пользователя в браузере; повторный запуск доступен в «Ещё».

Для явной замены всех обращений на два демонстрационных примера для каждого существующего дома: сначала сделайте резервную копию БД и остановите обработчики уведомлений, затем выполните `python -m scripts.reset_demo_issues --replace-all-issues`. Команда удаляет обращения, их сообщения, фотографии из БД, события и уведомления; физические файлы не удаляет. Профили, привязки квартир и заявки регистрации сохраняет. Это отдельная административная операция, не часть запуска приложения.
