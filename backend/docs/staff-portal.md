# Кабинет сотрудника УК

Кабинет открывается на `/staff/` того же сервера, где работает FastAPI. Локально это `http://127.0.0.1:8000/staff/`, на сервере — `https://ваш-адрес/staff/`. Next.js нужен только мини-приложению жителя. Дополнительный frontend-процесс для кабинета не требуется.

## Что реализовано

- Вход сотрудника по логину и паролю, выход, ограниченная по времени сессия.
- Доступ только к назначенным домам. Один сотрудник может обслуживать несколько домов одного ЖК. Назначения задаёт администратор через командную строку.
- Таблица обращений из бота и мини-приложения, поиск по номеру/заголовку/описанию, фильтры по дому, статусу и приоритету, страницы по 25 записей.
- Карточка: автор, дом, место (если указано), описание, категория, приоритет, фотографии и история статусов.
- Изменение статуса: «Новое», «В работе», «Решено». Изменение и задание на уведомление MAX сохраняются одной транзакцией.
- Сообщение автору до 1500 символов. Житель нажимает «Ответить сотруднику» в MAX, пишет текст, и ответ появляется в кабинете. Черновик другой жалобы в FSM сохраняется и восстанавливается.
- Обновление списка и диалога каждые 20 секунд, пока вкладка открыта. Ручное обновление доступно отдельно. Это polling, не WebSocket.
- Мобильная версия: таблица превращается в карточки, детали открываются на весь экран.

## Запуск из корня проекта на Windows

Используйте ту же БД и то же хранилище фото, что и бот. Корневой `.env` должен содержать `DATABASE_URL` и `MEDIA_ROOT=data/media`. Для локального HTTP добавьте `SESSION_COOKIE_SECURE=false`; для публичного HTTPS — `true`.

В PowerShell из `Project_Smart_City`:

```powershell
.\.venv\Scripts\python.exe -m pip install -r backend/requirements.txt
$env:PYTHONPATH = '.;backend'
.\.venv\Scripts\python.exe -m alembic -c backend/alembic.ini upgrade head
.\.venv\Scripts\python.exe -m scripts.manage_staff list
```

Команда `list` покажет существующие дома с ID. Создайте сотрудника, заменив имя, логин и ID дома своими:

```powershell
.\.venv\Scripts\python.exe -m scripts.manage_staff create manager --name "Анна Соколова" --house 1
```

Пароль вводится дважды в скрытом приглашении терминала; минимум 12 символов. Он не передаётся в аргументах команды и не выводится на экран. Для нескольких домов повторите `--house`: `--house 1 --house 2`.

Запустите сайт:

```powershell
.\.venv\Scripts\python.exe -m uvicorn smart_city_api.main:app --host 127.0.0.1 --port 8000 --loop smart_city_api.runtime:loop_factory
```

Откройте `http://127.0.0.1:8000/staff/`. В другом терминале из корня проекта запустите **один** экземпляр бота:

```powershell
.\.venv\Scripts\python.exe -m chatbot
```

Без бота изменения и сообщения сохраняются, но уведомления остаются в очереди. Для первого запуска PostgreSQL сначала примените миграции. Автоматическое `create_all` в боте не заменяет миграции.

Если запускаете команды из `backend/`, используйте `$env:PYTHONPATH = '..'`, настройки в `backend/.env` и команды из backend README. Убедитесь, что оба env-файла указывают на одну БД. Относительный `MEDIA_ROOT` кабинета всегда считается от корня репозитория, как у бота.

## Docker

Корневой Compose уже подключает общий volume `media`: бот пишет фото, API читает его в режиме read-only. Миграция `0004` создаёт таблицы сотрудников, сессий, переписки и уведомлений; существующие обращения сохраняются.

После пересборки сервисов выполните из корня (для production добавьте те же `-f compose.yaml -f compose.production.yaml`, что использовали при запуске):

```sh
docker compose --env-file .env.docker exec api python -m scripts.manage_staff list
docker compose --env-file .env.docker exec api python -m scripts.manage_staff create manager --name "Анна Соколова" --house 1
```

Сотрудник открывает `/staff/`. Обновлённый `deploy/nginx.conf` направляет этот путь в API. За reverse proxy корректно передавайте `Host` и `X-Forwarded-Proto`. Проверка входа допускает внешний HTTPS-origin из `CORS_ORIGINS`, только если он совпадает с переданным Host. Это учитывает TLS на Nginx и HTTP между Nginx и контейнером. Для определения реального IP клиента настройте доверие Uvicorn только к адресу вашего proxy (`FORWARDED_ALLOW_IPS`); иначе IP-лимит попыток будет общим для клиентов proxy, но ограничение по логину всё равно действует. Ошибка 403 «Источник запроса…» при входе обычно означает несовпадение host или отсутствие вашего HTTPS-origin в `CORS_ORIGINS`.

Старый отдельный `backend/compose.yaml` не запускает бот: для совместного запуска используйте корневой Compose. Если бот работает вне Docker, перенесите существующие фотографии в используемое общее хранилище или подключите одну абсолютную папку к обоим процессам; перенос файла БД сам по себе фотографии не переносит.

## Управление доступом

```sh
python -m scripts.manage_staff assign manager --house 1 --house 2
python -m scripts.manage_staff password manager
python -m scripts.manage_staff disable manager
python -m scripts.manage_staff enable manager
```

`assign` **заменяет** список домов целиком. Изменение домов/пароля и отключение сотрудника отзывают все его текущие сессии. Удаление сотрудника не предусмотрено: отключение сохраняет историю переписки и авторство. Учётных записей и паролей по умолчанию нет. После команды `disable` вход запрещён до `enable`.

## Как устроено

| Файл / каталог | Ответственность |
| --- | --- |
| `app/database/models.py` | Общие таблицы, в том числе `StaffUser`, `StaffHouse`, `StaffSession`, `IssueMessage`, `StaffNotification` |
| `backend/migrations/versions/0004_staff_portal.py` | Изменение схемы через Alembic |
| `backend/smart_city_api/core/staff_auth.py` | Хеширование паролей, сессии, CSRF и ограничение попыток входа |
| `backend/smart_city_api/api/routes/staff.py` | HTTP-маршруты кабинета и защищённая выдача фото |
| `backend/smart_city_api/services/staff.py` | Запросы по назначенным домам, транзакции статусов и сообщений |
| `backend/smart_city_api/schemas/staff.py` | Типы и проверка входящих данных / ответов API |
| `backend/smart_city_api/staff_web/` | HTML, CSS и JS интерфейса |
| `backend/scripts/manage_staff.py` | Создание аккаунтов, назначение домов, смена пароля, отключение |
| `chatbot/services/staff_notifications.py` | Доставка сохранённых уведомлений в MAX с повторными попытками |
| `chatbot/handlers/staff_messages.py` | Сценарий ответа жителя в боте |
| `chatbot/services/staff_messages.py` | Проверка автора обращения и сохранение ответа |

Таблица `StaffHouse` задаёт связь сотрудника с домами. Отдельной сущности «ЖК» пока нет: ЖК представлен набором назначенных домов. Если понадобятся название комплекса, организация, роли руководителей, добавьте `ResidentialComplex` и привяжите дома к нему отдельной миграцией.

Пароли хранятся как PBKDF2-HMAC-SHA256 с 600 000 итераций и случайной солью. Дорогая проверка выполняется в потоке, не блокируя asyncio. Сессия — случайный токен в HttpOnly-cookie; БД хранит только SHA-256 токена. Срок по умолчанию 8 часов (`STAFF_SESSION_HOURS`, 1–24). Есть CSRF-токен, проверка Origin, 10 попыток входа на логин и 40 на IP за 15 минут; лимиты общие для всех процессов API. Основа выбора параметров: [OWASP Password Storage](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html).

`request_id` предотвращает дублирование действий при повторе HTTP-запроса. При смене статуса `expected_status` обнаруживает одновременную правку другим сотрудником. История и очередь записываются в одной транзакции. Отправитель уведомлений сначала фиксирует короткую аренду задания в БД, затем обращается к MAX без открытой транзакции. Неудачная отправка повторяется с задержкой до часа. После аварии между ответом MAX и фиксацией `sent_at` возможен повтор: доставка **как минимум один раз**, а не гарантия exactly-once. «Отправлено в MAX» означает принятие API, а не прочтение жителем. Уведомления одной заявки отправляются последовательно; постоянная ошибка получателя задержит дальнейшие уведомления этой заявки.

Фотографии отдаются только после проверки прав на дом заявки. В ответах API нет локальных путей к файлам. SVG и произвольные пути не обслуживаются, публичного `/media` нет. Переписка принимает текст; новые вложения в ответ сотруднику пока не поддерживаются. В карточке отображаются последние 200 сообщений и уведомлений и 100 изменений статуса, более старые записи остаются в БД.

## Проверка перед показом

1. Житель отправляет обращение с фото в боте. Оно появляется у сотрудника назначенного дома; в другом доме не видно.
2. Сотрудник открывает фото, меняет статус на «В работе». Житель получает уведомление.
3. Сотрудник задаёт вопрос. Житель нажимает «Ответить сотруднику» и отвечает; ответ появляется в карточке.
4. Сотрудник отмечает обращение решённым. Статус виден и в мини-приложении.
5. После выхода закрытые API возвращают 401. Отключённый сотрудник войти не может.

Автотесты без настоящих уведомлений: `python -m pytest -q` из `backend`. Для проверок PostgreSQL задайте `TEST_POSTGRES_URL` отдельной тестовой БД. Тесты создают временные схемы. Ручной UI-предпросмотр: `python -m tests.serve_staff_preview` из `backend` с `PYTHONPATH=..`; создаются временная SQLite и случайный тестовый пароль, рабочий `.env` не читается, бот не запускается.
