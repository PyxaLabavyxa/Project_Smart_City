# Сервер 201.34.159.33

Приложение: https://201.34.159.33. Файлы на сервере: `/opt/dompulse`.
Сборка выполняется на сервере из текущих исходников, без Git push.

```sh
cd /opt/dompulse
docker compose --env-file .env.docker -f compose.yaml -f compose.production.yaml --profile bot up -d --build
docker compose --env-file .env.docker -f compose.yaml -f compose.production.yaml --profile bot ps -a
```

Nginx на хосте завершает TLS и проксирует `/api/` в `127.0.0.1:8000`, остальные
пути — в `127.0.0.1:3000`. Шаблон: `nginx.conf`. Frontend обращается к `/api/v1`
на том же origin. Порты приложений и БД напрямую в интернет не публикуются.

Сертификат Let's Encrypt выдан непосредственно на IP и автоматически продлевается
таймером `dompulse-certbot.timer` дважды в сутки. После продления deploy hook
перезагружает Nginx. Состояние: `systemctl list-timers dompulse-certbot.timer`.

Секреты находятся в `/opt/dompulse/.env.docker` с правами 0600, не в репозитории.
Настройки адреса и авторизации задаёт `compose.production.yaml`: локальный вход
отключён, используются MAX и Secure HttpOnly-cookie. URL мини-приложения необходимо
указать в настройках бота MAX. Обычный браузер без сессии получает приглашение
открыть приложение через MAX. Пользователь и привязка квартиры должны быть в БД.

Контейнерная БД создана отдельно от локальной. Локальные проверочные записи
не копировались на публичный сервер. Позже для проверки сценариев включён
`SAMPLE_DATA_ENABLED=true`: существующим и новым зарегистрированным жителям
выдаются до двух квартир, тестовые начисления, счётчики и обращения. Данные
добавляются при загрузке профиля; исходные счета и показания не заменяются.
Флаг отключается в `compose.production.yaml`, затем пересоздаётся API.
Данные сохраняются в Docker volumes.
Стартовые квартиры теперь выдаются сразу при регистрации в чатботе, а также
при загрузке профиля. Общий дом — ул. Садовая, 18: 15 этажей, два подъезда,
120 квартир. Каждый житель получает две разные свободные квартиры, с приоритетом
одной квартиры в каждом подъезде. Повторная регистрация сохраняет пару.
Распределение сериализовано блокировкой PostgreSQL; одна квартира не выдаётся
нескольким новым жителям. При полном заполнении добавляется следующий подъезд.
Перенос старых стартовых домов и распределение выполнены с сохранением ID квартир,
счетов и сообщений; резервные копии лежат в `/opt/dompulse/backups`.
Не выполняйте `docker compose down -v`, если данные нужно сохранить.
