# Подключение камер

Камеры подключаются по протоколу, а не по марке или типу сети Wi-Fi/Ethernet.
Нужен публичный адрес, доступный серверу. Приложение не обнаруживает устройства
в домашней сети и не работает с закрытыми облачными аккаунтами производителей.

| Тип в форме | Адрес | Просмотр |
| --- | --- | --- |
| HTTP / HTTPS, снимки | Прямой JPEG, PNG или WebP | Обновляемые снимки |
| MJPEG | HTTP(S) multipart-поток | Снимки и эфир |
| RTSP / RTSPS | Адрес потока IP-камеры/NVR | Снимки и эфир |
| ONVIF | HTTP(S) Device Service | Media1 GetProfiles / GetStreamUri → RTSP |
| HLS | HTTP(S) `.m3u8` | Снимки и эфир |
| RTMP / RTMPS | Адрес чтения существующего потока | Снимки и эфир |
| HTTP-видео | HTTP(S) FLV, MP4 или MPEG-TS | Снимки и эфир |

RTSP распространён у Hikvision, Dahua, Reolink, TP-Link/Tapo и других
производителей, но доступность протокола зависит от конкретной модели и прошивки.
Батарейные и облачные камеры могут не предоставлять внешний поток.
Аналоговая/USB-камера подключается через NVR/шлюз, предоставляющий один из этих протоколов.
WebRTC/облачные P2P-ссылки, звук, архив, PTZ, Media2-only ONVIF и двусторонняя связь
в эту реализацию не входят. Проверка реальных моделей остаётся необходимой.

## Пользовательский сценарий

В «Камеры → Добавить» выбрать протокол, указать адрес, при необходимости отдельные
логин/пароль, место и доступ. Перед сохранением сервер проверяет кадр. Недоступный
источник не сохраняется. Личная камера видна владельцу сразу; общедоступная —
остальным жителям дома после решения сотрудника УК. Сотрудник может проверить кадр,
одобрить, отклонить с причиной или удалить камеру в пределах обслуживаемых домов.

Владелец может открыть «Настройки камеры», изменить название, описание, URL, тип,
данные подключения и доступ или удалить камеру с подтверждением. Локация при
редактировании недоступна и отклоняется API. Общедоступная камера после изменений
снова становится pending. Изменённое подключение проверяется до сохранения;
изменение только названия не требует доступности камеры. Версия настроек защищает
от перезаписи изменений из другого окна. Пароль не возвращается в форму: можно
оставить сохранённый, заменить или явно очистить его.

У видеоисточников play находится на самом изображении; отдельной кнопки эфира
нет. Остановка также доступна на изображении. «Обновить кадр» остаётся у снимков.

Для ONVIF используется первый профиль либо указанный token. Камера часто сообщает
внутренние адреса: Media XAddr получает публичный origin исходного Device Service,
а RTSP URI — его hostname. Внешний RTSP-порт можно задать отдельно. Таким образом,
ONVIF HTTP(S) и RTSP должны быть доступны на одном публичном имени/IP.
HTTP Basic/Digest для снимков и ONVIF выбираются в форме. Для потоков авторизацию
обрабатывает FFmpeg. Для RTMP/RTMPS сначала используется штатная авторизация;
если видео не получено, выполняется одна попытка с `user`/`pass` в query для
совместимости с MediaMTX. Явно заданные query-параметры авторизации сохраняются.
HTTPS, RTSPS и RTMPS требуют действительный сертификат для указанного имени узла.

Эфир без звука преобразуется в MJPEG, до 4 кадров/с и 960×540, чтобы работать в
браузерах мини-приложения с H.264/H.265 и другими декодируемыми FFmpeg кодеками.
Соединение ограничено 40 секундами и обновляется клиентом; при уходе со страницы
или скрытии приложения эфир отключается. Одновременно допускается 6 операций
обработки; при перегрузке возвращается ошибка с предложением повторить.
Карточки вне экрана не опрашивают камеры.

## Развёртывание и данные

Образ обработчика собирает FFmpeg 8.0.3 из официального архива с проверкой SHA-256.
Первая сборка занимает больше времени; последующие используют Docker-кеш.
При запуске вне этого образа нужен FFmpeg 8 с GnuTLS и параметрами `tls_verify`
и `ca_file` у RTSP demuxer: FFmpeg 7 не поддерживает проверяемое RTSPS-подключение
этим способом. После обновления кода нужно пересобрать образ `camera-worker`.

Основной `compose.yaml` запускает `camera-worker`. Его HTTP API не публикуется
на хост. Он не имеет БД и смонтированных данных приложения. При запуске firewall
запрещает новые исходящие подключения к непубличным IPv4/IPv6-адресам, в том числе
через редиректы, ONVIF, HLS-сегменты и DNS rebinding. Без успешной установки правил
worker не запускается. Процесс обработки работает без root и Linux capabilities.
Исключения: DNS Docker и root healthcheck. Не отключать firewall ради LAN-адресов.

Новые подключения (включая URL с токенами и пароли) хранятся в `source_config`
с шифрованием Fernet. Ключ — `MEDIA_ROOT/camera-source.key`, права 0600.
**Резервировать этот файл вместе с БД**; потеря ключа делает подключения нечитаемыми.
Ключ нельзя отдавать через HTTP или включать в Git. Worker получает данные только
на время запроса. Другим жителям и сотрудникам URL/пароли новых подключений не выдаются.
Владелец получает URL в настройках, а сохранённый пароль не возвращается никому.
Права проверяются до каждого запроса кадра и каждого нового соединения эфира.
Уже открытый эфир после изменения доступа может работать до 40 секунд.

Миграция `0016` сохраняет старые камеры/фотографии. Старые HTTPS-снимки продолжают
загружаться прежним способом. Downgrade заблокирован, пока существуют зашифрованные
подключения: сначала нужен экспорт/план их удаления, иначе потеряются данные.

Локальные тестовые заявки добавляются явно, без автозапуска на сервере:
`docker compose --env-file .env.docker -f compose.yaml -f compose.local.yaml exec api python -m scripts.seed_camera_requests`.

## Проверки и источники

`tests/test_camera_decoding.py` проверяет повторную авторизацию RTMP, выбор HLS,
TLS-параметры и закрытие декодера при отмене/таймауте запроса.
`tests/test_camera_sources.py` проверяет форматы, запрет опасных адресов, шифрование,
проверку до сохранения, идемпотентность и доступ. `tests/test_resident_cameras.py`
сохраняет проверки модерации/CSRF/приватности. Для проверки настоящего FFmpeg
использованы изолированные HTTP/ONVIF fixtures из `tests/camera_protocol_fixture.py`
и MediaMTX 1.15.2; `scripts/check_camera_protocols.py` проверяет снимки и эфир всех
перечисленных типов, а также запрет приватного HLS-сегмента. Это проверка протоколов,
не сертификация совместимости с физическими камерами.
