# ДомПульс

Dockerfile для standalone-сборки находится в этой папке. Общий запуск с API,
PostgreSQL и ботом: [DOCKER.md](../DOCKER.md).

Мини-приложение жителя на Next.js, TypeScript и CSS Modules. Данные загружаются
из FastAPI и PostgreSQL: дома, квартиры, обращения, переписки, ЖКХ, камеры и работы.
Локальные моки в приложении не используются.

## Запуск

Node.js 22.13+:

```powershell
npm ci
Copy-Item .env.example .env.local
npm run dev
```

`NEXT_PUBLIC_API_BASE_URL` — адрес API с `/api/v1`, по умолчанию
`http://localhost:8000/api/v1`. Frontend: `http://localhost:3000`.
Используйте одинаковое имя хоста (`localhost` либо `127.0.0.1`) для локальных
API и frontend, чтобы cookie работали как same-site. Origin должен быть разрешён
в CORS backend. На HTTPS включите Secure-cookie; секреты хранятся только на сервере.
Переменная NEXT_PUBLIC встраивается при сборке: после её изменения нужна пересборка.

Обычный вход — через MAX. Подписанные параметры передаются API для проверки,
после чего используется HttpOnly-cookie. В обычном браузере без действующей сессии
приложение предлагает открыть его через MAX. После истечения сессии откройте
мини-приложение заново. Токены не сохраняются в localStorage/sessionStorage.

Для локальной разработки включите `NEXT_PUBLIC_ENABLE_LOCAL_LOGIN=true` и
серверный `LOCAL_LOGIN_ENABLED=true`; секрет и создание проверочного жителя описаны
в backend README. Сверху появится переключатель «Локальный / MAX». Локальный режим
отмечен в интерфейсе, данные сохраняются в PostgreSQL. Выбор MAX завершает локальную
сессию и требует настоящего входа через MAX. После перезагрузки при включённом
флаге снова выбран локальный режим. Для публичной сборки оба флага выключаются.

Инструкция API, PostgreSQL, миграций и переноса базы чатбота: [backend](../backend/README.md).

## Основные сценарии

- Главная: выбор своей квартиры/дома, последние активные обращения, план, сервисы и работы.
- Обращение: место → категория → описание → проверка → запись на сервере → карточка.
  Возврат между шагами сохраняет черновик; ошибка не очищает поля. Повторный submit
  заблокирован, повтор сетевого запроса использует тот же ключ идемпотентности.
  Черновик хранится только в памяти вкладки и очищается при смене квартиры/перезагрузке.
- План: этажи и номера квартир из БД; произвольная нумерация не пересчитывается формулой.
- Сообщения: история и отправка с выбранной квартиры, ручное обновление переписки.
- ЖКХ: данные лицевого счёта, квитанции и зарегистрированные приборы; показания
  сохраняются на сервере. Приём платежей пока отключён.
- Камеры: только зарегистрированные камеры и кадры; нет подключения — нет вымышленного видео.
- Здоровье: индикатор по доступным обращениям; не телеметрия и не медицинская/техническая экспертиза.

Отсутствующие данные показываются пустыми состояниями. Сетевая ошибка содержит
кнопку повтора. Чужие дома и квартиры отсекаются сервером.
Доступны статусы существующей БД: новое, в работе, выполнено.

## Проверка

```powershell
npm run lint
npm run typecheck
npm test
npm run build
npm start
```

Войти через MAX, создать обращение, открыть карточку и перезагрузить страницу:
запись должна остаться. Проверить возврат на план, список и фильтры, отправку
сообщения, отклонение уменьшенного показания и сохранение корректного.
Проверить desktop и ширину 320px. Фикстуры unit-тестов находятся в `tests/fixtures`;
локальный проверочный житель создаётся отдельно в БД командой `python -m scripts.seed_local`.

Публичное развёртывание, фактический запуск внутри MAX, платежи, поставщики ЖКХ,
уведомления и подключение реальных камер проверяются отдельно при наличии интеграций.
