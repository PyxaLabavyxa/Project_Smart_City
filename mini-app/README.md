# ДомПульс — мини-приложение

Интерфейс жителя на Next.js, TypeScript и CSS Modules. Данные домов, квартир, обращений, переписок и ЖКХ поступают из API. Общий запуск с PostgreSQL и ботом: [DOCKER.md](../DOCKER.md).

## Локальный запуск

Нужен Node.js 22.13 или новее. Из каталога `mini-app`:

```sh
npm ci
npm run dev
```

До запуска создайте `.env.local` по [.env.example](.env.example), если его ещё нет:

| Переменная | Назначение |
| --- | --- |
| `NEXT_PUBLIC_API_BASE_URL` | Адрес API с `/api/v1`, локально `http://localhost:8000/api/v1` |
| `NEXT_PUBLIC_ENABLE_LOCAL_LOGIN` | Переключатель локального входа; для публичной сборки `false` |

Frontend доступен по http://localhost:3000. API запускается отдельно: [backend README](../backend/README.md). Используйте одинаковый hostname для API и frontend и разрешите origin frontend в CORS. Секретов в этих переменных быть не должно. Значения `NEXT_PUBLIC_*` встраиваются при сборке.

Остановка dev-сервера — Ctrl+C, повторный запуск — `npm run dev`. Для сборки используется `npm run build`; Dockerfile упаковывает standalone-сборку.

## Вход и данные

Основной вход — через MAX: сервер проверяет подписанные параметры и выдаёт HttpOnly-cookie. Без сессии приложение предлагает открыть его в MAX.

Для работы в браузере включите `NEXT_PUBLIC_ENABLE_LOCAL_LOGIN=true`, серверный `LOCAL_LOGIN_ENABLED=true` и подготовьте локального жителя по инструкции backend. Появится переключатель «Локальный / MAX». Смена режима завершает сессию. После изменения frontend-флага перезапустите dev-сервер или пересоберите образ.

Отдельного mock-адаптера нет: приложение читает API. Подготовленные данные создаются в PostgreSQL явно, через seed-команды backend. Пустые ответы и ошибки показываются в интерфейсе; ошибки допускают повтор запроса.

## Сценарии

- Главная: выбор квартиры и дома, активные обращения, план и сервисы.
- Обращения: список и фильтры, создание по шагам, карточка и история статусов.
- План: выбор подъезда, этажа и квартиры из серверной структуры.
- Сообщения: переписка от выбранной квартиры, отправка и ручное обновление.
- ЖКХ: квитанция и передача показаний зарегистрированных приборов.
- Камеры: доступные источники кадра.
- Здоровье дома: показатель на основе обращений.

Возврат между шагами формы сохраняет введённые значения, сетевая ошибка не очищает поля. Повторная отправка защищена ключом идемпотентности. Черновик хранится в памяти и сбрасывается при смене квартиры или перезагрузке вкладки.

Платежи, push-уведомления, видеотрансляции и интерфейс УК не подключены. Показатель здоровья не является данными инженерного мониторинга.

## Проверка

```sh
npm run lint
npm run typecheck
npm test
npm run build
```

Создайте обращение, откройте карточку и обновите страницу: запись должна остаться. Проверьте возврат к списку и месту на плане, отправку сообщения, сохранение показания и ошибку при уменьшении значения. Проверьте desktop и ширину 320px.

Фикстуры unit-тестов находятся в `tests/fixtures`. Основной сценарий и условия проверки в MAX описаны в [корневом README](../README.md#проверка-основного-сценария).
