# Домовед — мини-приложение

Приложение жителя для MAX на Next.js, React и TypeScript. Использует API из [backend](../backend/README.md). Запуск всего проекта в Docker описан в [DOCKER.md](../DOCKER.md).

## Запуск

Требуется Node.js 22.13 или новее. Выполните из каталога `mini-app`:

```powershell
npm ci
Copy-Item .env.example .env.local
npm run dev
```

Если `.env.local` уже существует, используйте его. Приложение доступно по адресу `http://localhost:3000`; API запускается отдельно.

| Переменная | Назначение |
| --- | --- |
| `NEXT_PUBLIC_API_BASE_URL` | Адрес API с `/api/v1`, по умолчанию `http://localhost:8000/api/v1` |
| `NEXT_PUBLIC_ENABLE_LOCAL_LOGIN` | Разрешает локальный вход при значении `true`; для публичной сборки — `false` |
| `NEXT_PUBLIC_SHOW_LOCAL_LOGIN_CONTROLS` | Показывает панель выбора локального пользователя при значении `true`; по умолчанию панель скрыта |

Для локального входа также включите `LOCAL_LOGIN_ENABLED` в backend, задайте `LOCAL_SESSION_SECRET` и выполните `python -m scripts.seed_local`. Используйте одинаковый hostname для приложения и API; адрес приложения должен входить в `CORS_ORIGINS`.

Переменные `NEXT_PUBLIC_*` встраиваются при сборке и доступны браузеру. После их изменения перезапустите dev-сервер или пересоберите приложение.

## Возможности

- Регистрация: ФИО, выбор УК, дома и квартиры. Состояние регистрации общее с ботом.
- Квартиры: добавление нескольких квартир и переключение между ними. Одна квартира может быть привязана к нескольким жильцам.
- Обращения: создание с фотографиями и местом на плане, фильтры, статусы и история.
- План дома: интерактивный фасад, выбор подъезда, этажа, квартиры и общей зоны.
- Сообщения: переписка между квартирами и чат с УК внутри своего обращения.
- ЖКХ: квитанции и передача показаний счётчиков одной формой.
- Камеры: просмотр кадров, добавление своей камеры по ссылке с автоматическим определением типа и проверкой кадра, выбор места на плане и фильтры «Мои камеры», подъезд, этаж, помещение.
- Здоровье дома: показатель по обращениям и история за 7, 14 или 30 дней. Нажатие на график выбирает дату.
- Контакты УК, информация о доме, обучение и переключение темы.

Раздел «План дома» открывает фасад по адресу `/house`, выбранный этаж — `/plan`. Контакты УК доступны на `/contacts`. Квитанции и показания переключаются вкладками в разделе «ЖКХ».

В разделе «Камеры» кнопка «Добавить камеру» открывает форму с тем же выбором места, что в обращениях. Панель фильтров изначально скрыта и открывается кнопкой «Фильтры»: доступны тип камер (все, мои, общедоступные), подъезд, этаж и помещение. Личная камера доступна только создателю сразу после добавления. Общедоступная камера до одобрения УК видна только владельцу; после одобрения — жителям этого дома. При отклонении владелец видит причину. Проверить решение можно в карточке камеры, обновить список — кнопкой рядом с количеством камер.

Вставьте публичную ссылку на камеру: тип подключения определится автоматически (снимки, RTSP/RTSPS, RTMP/RTMPS, HLS, MJPEG, ONVIF или HTTP-видео). Под полем отображается короткий статус проверки и полученный кадр либо ошибка с кнопкой повтора. Некорректная ссылка проверяется локально без запроса к серверу. Изменение ссылки и данных доступа запускает новую проверку; устаревшие ответы игнорируются. Тип можно указать вручную в дополнительных параметрах. Сервер подключается через изолированный camera-worker, логин и пароль вводятся отдельно и хранятся зашифрованными. Тестовые камеры используют локальные изображения.

Для двора, парковки и территории дома подъезд и этаж отключены и показывают «Нет подъездов» / «Нет этажей». При смене места несовместимые фильтры очищаются. У входной группы доступен только первый этаж. Эти правила общие для камер и обращений. Подъезд и этаж в формах создания выбираются обычными выпадающими списками без отдельного модального окна.

При первом входе без квартиры открывается регистрация. В тестовом режиме заявки принимаются автоматически. После привязки запускается обучение; повторный запуск доступен в разделе «Ещё».

В разделе «Ещё → Настройки → Оформление» доступны карточки светлой, тёмной и системной тем с миниатюрами интерфейса. Выбранная тема сохраняется в браузере; явная светлая тема запрещает автоматическое затемнение страницы браузером. Обучение учитывает видимую область мобильного окна и её смещение, а при отсутствии CSS zoom ограничивает высоту блока с прокруткой вместо расширения его ширины. Настройки уведомлений MAX сохраняются в аккаунте отдельно для сообщений соседей, ответов УК, статусов обращений и объявлений. Рассылка общих объявлений пока не подключена.

При старте главная ждёт завершения параллельных запросов справочника квартир, обращений, сообщений и ЖКХ. Ошибка отдельного сервиса отображается в его блоке и не закрывает доступ к работающим разделам; ошибка справочника квартир имеет общий повтор загрузки. При последующих фоновых обновлениях главная не скрывается. Прямые переходы в другие разделы не ждут данных главной.

Камеры подключаются при открытии их раздела. При первом открытии список показывает заготовки карточек; при повторном — предыдущий список сразу, с обновлением в фоне. При ошибке обновления карточки сохраняются рядом с кнопкой повтора. Этот список хранится только в памяти текущего сеанса и сбрасывается при смене квартиры или пользователя. Черновик обращения хранится в памяти и сбрасывается при перезагрузке или смене квартиры.

Личная переписка использует `?from=<ID своей квартиры>`: перезагрузка и возврат с плана восстанавливают точный дом, недоступная квартира из ссылки не подменяется другой. В шапке показан адрес. Прочитанными отмечаются уведомления только показанной беседы до последнего видимого входящего сообщения.

Список квартир обновляется при возвращении в приложение и раз в 20 секунд, обращения — раз в 10 секунд, пока приложение видно. Одинаковый профиль сохраняет прежние ссылки на данные, чтобы обновление не сбрасывало формы. Кнопка «Продолжить позже» у обращения сохраняет черновик только в текущем сеансе; рядом явно указан срок хранения. Перед перезагрузкой с заполненным черновиком браузеру передаётся запрос предупреждения (поддержка зависит от webview). Личные данные и фотографии в постоянное браузерное хранилище не записываются.

При первом подтверждении квартиры по QR/ссылке `home_house_<id>` открывается главная и обучение для статуса `not_started`. Кнопки чата `report_house_<id>`, `issues_house_<id>` и `contacts_house_<id>` откладывают автоматическое обучение, чтобы не прерывать нужное действие. Пройденное или пропущенное обучение автоматически не повторяется; повтор доступен в «Ещё».

## Сборка и проверки

```powershell
npm run lint
npm run typecheck
npm test
npm run build
```

[Dockerfile](Dockerfile) использует standalone-сборку Next.js. Маршруты находятся в `app/`, экраны и компоненты — в `src/`, статические файлы — в `public/`.

## Ограничения

Оплата ЖКХ демонстрационная: платёжный провайдер не подключён. Выбор СБП или карты не проводит оплату. PDF-квитанции и документы дома пока не загружаются; кнопки сообщают об этом. Если УК не указала дополнительные контакты, интерфейс показывает отсутствие данных. Доступность камер зависит от публичного источника и настройки camera-worker. Здоровье дома рассчитывается по доступным обращениям и не является показанием инженерных датчиков.

### Пригласить соседей

«Ещё → Пригласить соседей» (`/invite`) показывает приглашение текущего дома: ссылка, QR-код и листовка A4 для печати в PDF/PNG. При переключении дома приглашение загружается заново, без показа ссылки предыдущего дома. На белой листовке размещён машущий Жорик без цветного фона (`zhorik-invitation.png`); QR остаётся чёрным на белом в обеих темах.

При переходе из MAX или по `?startapp=report_house_<id>`/`home_house_<id>` сохраняются дом и нужный раздел. В регистрации подставляются соответствующие УК и адрес, житель вводит ФИО и квартиру. После одобрения открывается исходный раздел; при ожидании ответа УК дом не считается привязанным. Параметр остаётся в URL на время регистрации, чтобы перезагрузка не теряла выбранный дом. Это только адрес назначения: доступ всегда проверяет API. «На главную Домоведа» снимает этот контекст. Автоматическое обучение откладывается при таком переходе; вручную его можно запустить через «Ещё».

В MAX скачивание использует `WebApp.downloadFile` и публичный HTTPS адрес файла; при обычном открытии в браузере используется загрузка файла через Blob. В локальном режиме ссылки ведут в MAX, поэтому сквозную проверку опубликованного мини-приложения выполняют после его отдельного развёртывания. Для проверки локального сценария можно открыть `/?startapp=report_house_<id>` при включённом локальном входе. Производственный доступ и подтверждение квартир этим не обходятся.

В веб-версии MAX, включая сохранённое на экран iPhone приложение Safari, сначала используется обычная cookie-сессия. Если браузер блокирует сторонние cookies и API отвечает 401, клиент один раз повторяет запрос с исходным подписанным `WebAppData` в заголовке `Authorization`, а затем использует этот способ в текущем сеансе. API по-прежнему проверяет подпись, срок действия и доступ к дому. Данные входа хранятся только в памяти; в URL, localStorage и новые cookies они не записываются. При истечении срока нужно заново открыть мини-приложение из MAX. Фотографии обращения и чатов при недоступных cookies загружаются тем же авторизованным клиентом во временные Blob URL; обычная загрузка и её отложенный режим сохранены. Если MAX не открыл само мини-приложение или не передал подписанные данные, этот механизм не заменяет вход через MAX.
