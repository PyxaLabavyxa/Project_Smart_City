# ДомПульс

Frontend приложения для обращений жителей. Next.js, TypeScript, CSS Modules.

На главной отображаются состояние дома, последние активные обращения,
фасад с выбором этажа, ЖКХ, переписки и работы в доме. В разделе «Обращения»
доступны полный список, карточка с историей статусов и форма создания.
Есть светлая и тёмная темы. Главная и «Ещё» связывают разделы приложения.
На нижней панели доступны дом, обращения, ЖКХ, камеры и дополнительные разделы.
План доступен с главной страницы и из меню «Ещё».
Вложенные экраны сохраняют выделение своего раздела.

## Навигация

Разделы `/health`, `/messages`, `/info`, `/cameras` и `/cameras/[id]`
доступны с главной страницы и из меню «Ещё».
Из плана можно перейти к созданию обращения или сообщениям.

Проверка связей:

- Главная → все обращения → карточка → план дома.
- Главная → сообщить о проблеме → создать обращение → карточка.
- Главная → план / камеры / здоровье дома / сообщения.
- План → создание обращения → отмена возвращает к плану.
- План → сообщения → «К плану дома».
- Ещё → информация о доме → назад.
- Камеры → карточка камеры → все камеры; неизвестный ID даёт путь к списку.

Ссылки возврата ведут к явному разделу приложения и работают при открытии
страницы напрямую. Параметр `from=plan` у формы меняет
только возврат; произвольные внешние адреса не принимаются.

Backend не подключён. Начальный список использует тестовые данные из
`src/entities/issue/model/demo-issues.ts`. Новые обращения хранятся в памяти
до перезагрузки страницы и не отправляются во внешние сервисы.

## Возможности разделов

- ЖКХ (`/utilities`): квитанция за сентябрь, расшифровка начислений, лицевой
  счёт и счётчики квартиры жителя. Данные и условные тарифы находятся в
  `src/mocks/utility-account.ts`; это не реальные начисления поставщиков.
  Состав приборов и их номера доступны только для чтения. Житель вводит
  показания зарегистрированного прибора по ID; неизвестный ID и уменьшение
  показания отклоняются. Показания следующего
  периода не пересчитывают уже выставленную квитанцию. Состояние хранится
  в памяти на время работы приложения, отдельно по дому и квартире.
  API регистрации приборов, передачи показаний и расчёта счетов пока нет.
  После перезагрузки восстанавливаются исходные тестовые данные.
- Оплата: выбор QR или карты. QR содержит текст `DOMPULSE PAYMENT UNAVAILABLE`;
  платёжных реквизитов в нём нет. Форма принимает для проверки только номер
  `4242 4242 4242 4242`, срок `12/30`, код `123`. Не вводите настоящие реквизиты.
  Они не отправляются, не логируются и не сохраняются в браузерное хранилище;
  поля очищаются при закрытии или смене способа оплаты. Кнопка не списывает
  деньги и не меняет статус счёта. Для реальной оплаты нужен серверный
  платёжный контракт и форма платёжного провайдера вместо локальных полей.
- Сообщения: список переписок с поиском, последним сообщением и датой;
  отдельный диалог с авторами по квартирам и временем. На мобильном есть
  возврат к списку. Черновики отдельных квартир сохраняются при переключении.
  Исходная история квартир 69, 70, 72 — тестовая, новые сообщения остаются
  локальными. Реальная доставка и подтверждения прочтения не реализованы.

Проверка ЖКХ: открыть раздел из нижней панели, проверить сумму и строки,
ввести показание меньше предыдущего, затем корректное. Проверить, что нет
добавления, удаления и редактирования реквизитов приборов. Перейти в другой раздел и вернуться. Открыть QR,
затем карту, заполнить тестовые поля: счёт должен остаться неоплаченным.
Проверка чата: открыть квартиру 69, написать сообщение, вернуться к списку,
открыть квартиру 70 и проверить независимость истории и черновика.

- План: по умолчанию два подъезда, девять этажей, четыре квартиры на этаже.
  Нумерация непрерывная и учитывает индивидуальные настройки этажей. Выбор квартиры,
  коридора, лестницы, лифта, технической зоны и входной группы на первом этаже.
  При смене этажа или подъезда выбор сбрасывается на коридор. Для помещения
  отображаются связанные обращения и их состояние.
  Квартиру можно найти по номеру. Схема помещений общая для плана и первого
  шага создания обращения; выбранное место выделяется цветом и контуром.
  Большие этажи разбиты на участки по шесть квартир. Поиск открывает нужный
  участок. Дом, двор и парковка доступны как отдельные места обращения.
- Обращения: совместные фильтры по статусу, категории, подъезду, этажу,
  помещению и поиск по названию, описанию и месту; сброс и пустая выдача.
  Быстрые переключатели показывают активные, решённые или все обращения.
  Создание проходит через место, категорию, описание и проверку перед отправкой.
  Место передаётся из плана и сохраняется в новой записи. Черновик не теряется
  при переходах между шагами и разделами. Активные обращения той же категории
  в выбранном помещении показываются как возможные дубликаты.
- Камеры: состояния загрузки, ошибки и просмотра тестового кадра. Для парковки
  первая загрузка завершается ошибкой, повторная — успешно; камера двора остаётся
  на обслуживании. Кадр условный, видеотрансляции нет.
- Здоровье дома: общий показатель, оценки систем и ссылки на обращения
  с соответствующим фильтром категории. Подтверждение решения обновляет показатели.
- Сообщения: выбор подъезда, этажа и квартиры получателя. Свою квартиру 71
  выбрать нельзя. Выбранная на плане квартира становится получателем.
  Для квартиры 69 есть начальная история. Отправка добавляет сообщение локально,
  переписки и черновики разных квартир разделены. Контакты жильцов не отображаются.
- Житель может подтвердить решение или вернуть проблему в работу.
- Структура дома доступна только для просмотра. Редактора подъездов, этажей
  и квартир в приложении жителя нет. Дом передаётся в `HouseSelectionProvider`
  извне; сейчас подключены локальные данные, далее — ответ backend.

Подтверждение решений работает локально в памяти страницы и сбрасывается
при перезагрузке. Доступен только интерфейс жителя. Личные данные не сохраняются
в браузерное хранилище. Выбор подъезда и этажа открывает панель с числами;
Escape закрывает её, стрелки перемещают фокус, Enter выбирает значение.

Модель дома находится в `src/entities/house/model/`, состояния камер — в
`src/_pages/cameras/model/demo-cameras.ts`, показатели систем — в
`src/_pages/services/model/demo-health.ts`. Это локальные тестовые данные,
а не ответы API, видеотрансляции или телеметрия. Обращения, сообщения и черновики
хранятся в памяти до перезагрузки; localStorage не используется. Из карточки
обращения открывается его место на плане. Параметры места в ссылке проверяются.

Создание обращений, отправка сообщений и загрузка кадра отделены от UI
интерфейсами IssueGateway, MessageGateway и CameraGateway. Моковые реализации
находятся в src/mocks. Провайдеры подключены в src/_app/layouts/app-providers.tsx;
CameraPreview принимает отдельный gateway. Для подключения backend нужно
реализовать эти интерфейсы через fetch и согласовать DTO с сервером.
API-адреса не заданы: готового HTTP-контракта в репозитории нет.

Статусы `accepted`, `assigned`, `awaiting-confirmation` — только UI-состояния;
backend определяет `new`, `in_progress`, `resolved`. Существующие frontend
`in-progress` и `completed` не переименованы; сетевого преобразования нет.
Категории соответствуют понятиям backend; «Уборка» сохранена как локальная
категория старой формы. Поле `place` у обращений — структурированная локальная
привязка к дому, не поле текущей backend-модели.

Проверка: план → подъезд 1, этаж 1 (квартиры 1–4) → подъезд 2, этаж 9
(69–72) → коридор → протечка. В обращениях выбрать «Активные» и
«Водоснабжение», затем этаж 8 (пусто) и сбросить фильтры. Открыть четыре
камеры, показатели систем, выбрать квартиру 70 в сообщениях и сменить этаж.

## Запуск

Требуются Node.js 22.13+ и npm. Из корня репозитория:

```sh
cd mini-app
npm ci
npm run dev
```

Приложение доступно по адресу http://localhost:3000.
Переменные окружения для текущей версии не нужны.

## Проверки и сборка

```sh
npm run lint
npm run typecheck
npm test
npm run build
```

`npm test` проверяет нумерацию, границы структуры, привязку помещений,
историю статусов и изменение показателей после подтверждения решения.

Запуск собранного приложения:

```sh
npm start
```

## Структура

Общие цвета, размеры, радиусы и типографика заданы в
`src/shared/styles/tokens.css`. Базовые кнопки и статусы используют
`controls.module.css`. Шрифт Onest хранится локально. На desktop ширина
контейнера — до 1184px, навигация расположена под шапкой; до 760px она
закреплена снизу с учётом safe area. Светлая и тёмная темы используют одни компоненты.

Проект организован по Feature-Sliced Design.

```text
app/            Маршруты Next.js
src/
  _app/         Корневой layout и глобальные стили
  _pages/       Экраны
  widgets/      Шапка и навигация
  features/     Создание обращения, переключение темы
  entities/     Данные и компоненты обращений
  shared/       Общие стили и дизайн-токены
```

Слои App и Pages названы `_app` и `_pages`, чтобы не пересекаться
с каталогами маршрутизации Next.js. Внешние импорты слайсов идут через `index.ts`.

Для ручной проверки: создать обращение, открыть его карточку и вернуться
к списку. Новая запись должна появиться на главной среди активных.
Проверить обязательные поля формы и отображение на ширине 320px.

ЖКХ получает данные через `UtilitiesGateway`: `loadAccount()` и
`saveReading(meterId, value)`. Источник подключён в `app-providers.tsx`.
Сейчас используется локальная реализация; HTTP-маршрутов ЖКХ в backend нет.
При подключении сервера лицевой счёт должен определяться авторизацией,
а принадлежность прибора и допустимость показаний проверяться сервером.
Клиентские ограничения не заменяют серверную проверку. Пользовательский
интерфейс не создаёт приборы и не меняет их заводские номера или ресурс.
